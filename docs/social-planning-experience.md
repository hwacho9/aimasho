# 모임 도구에서, 우리만의 기록으로

브랜치: `codex/social-planning-experience` · 2026-09-08

## 제품 방향과 레퍼런스

비회원에게는 가입 없이 끝까지 쓸 수 있는 모임 도구, 회원에게는 친구와 함께한 모임을 쌓는 작은 SNS를 제공한다. 공개 팔로워 경쟁보다 다음 약속과 함께한 기록을 연결한다.

- [Partiful — RSVP sites](https://partiful.com/invitations/rsvp-sites): 앱 설치·계정 없이 초대에 응답하는 흐름을 참고. aimasho에서는 생성과 참가 모두 비회원 흐름을 유지한다.
- [Partiful — Guest polls](https://help.partiful.com/en-us/articles/15525422-can-i-poll-or-survey-my-guests): 날짜 투표와 모임 내용에 대한 의견 수집을 참고. 식사·활동 투표를 날짜 확정 전에도 쓰도록 기존 기능을 더 쉽게 노출한다.
- [TimeTree — Album](https://timetreeapp.com/intl/en/newsroom/2025-02-17/album): 앞으로의 일정과 지난 추억을 같은 맥락에서 보는 방식을 참고. 이번 구현은 사진 대신 280자 한 줄 기록부터 제공한다.
- [TimeTree — Shared event visibility](https://support.timetreeapp.com/hc/en-us/articles/900002172746-Can-other-calendar-members-see-my-events): 참여한 사람끼리 공유하는 범위를 참고. 전 세계 공개 피드는 만들지 않는다.

사용 흐름을 참고했으며 화면·로고·이미지를 복제하지 않았다.

## 구현한 흐름

| 대상 | 시작 | 한곳에서 하는 일 | 돌아올 이유 |
| --- | --- | --- | --- |
| 비회원 | 식사 / 활동 / 자유 모임 | 이름·제목·후보 날짜 → 초대 링크 → 날짜/내용 투표, 장소, 당일 플랜, 정산 | 같은 익명 계정의 기존 모임 이어가기 |
| 회원 | 나의 소셜 홈 | 우리 / 약속 / 친구 / 추억 | 친구별 완료 기록, 다음 약속, 그룹, 한 줄 추억 |

### 게스트

- 후보 날짜 기본 4개에서 2개로 축소. 1개만 남기거나 최대 12개까지 추가 가능.
- 설명·시간, 기간/요일 생성, 응답 마감·권한은 펼쳐서 설정. 기존 기능 유지.
- 출발지 수집 기본 OFF. 참가자 플랜 공동 편집 기본 ON이며 호스트 전용으로 바꿀 수 있음.
- 식사/활동 템플릿은 해당 투표를 기본 활성화. 제목은 사용자가 입력한다.
- 웹 모임 방에 날짜·할 일·장소·당일 플랜·정산 바로가기 추가.
- 웹/Flutter에서 현재 익명 계정으로 만들거나 참여한 미확정 모임도 표시.
- 익명 계정은 앱 삭제·브라우저 데이터 삭제·기기 변경 시 접근을 잃을 수 있어 링크 보관을 안내. 계정 간 기록 병합을 새로 구현한 것은 아니다.

### 회원

- 큰 비회원 소개 대신 다음 확정 약속, 조율 중 모임, 친구 기록, 최근 추억을 노출.
- 날짜가 지났지만 완료하지 않은 본인 모임은 별도로 마무리를 안내. 자동으로 만남 횟수를 증가시키지 않는다.
- 약속 탭은 기존 캘린더·타임라인·검색·필터 사용. 지난 날짜인데 완료하지 않은 약속도 전체 목록에서 사라지지 않는다.
- 친구 탭은 같은 모임에 참여한 등록 계정을 연결로 표시. 비회원 이름은 모임 동행자에는 보이지만 친구 프로필로 공개되지 않는다.
- 완료 모임 횟수와 진행 중 모임 횟수 분리. 이정표는 1 / 3 / 8 / 15 / 30회. 친밀도를 측정한 점수가 아니다.
- 친구 상세는 둘이 공유한 모임과 기존 Journey 플레이어로 연결. 그룹 상세·초대·생성 유지.
- 완료 모임에 회원 본인이 280자 한 줄 기록 작성·수정·삭제 가능. 웹과 Flutter 모두 지원.
- 추억 피드는 내가 참여한 완료 모임만 표시. 펼치기 시에만 글을 불러온다.
- 본인의 `NO`, 친구의 `NO`, 취소된 모임은 새 만남 집계에서 제외. 응답 미등록/미정은 참가자 명단과 호스트 완료 기록을 기준으로 집계하므로 실제 참석 증명이 아니다.

## 데이터와 권한

새 함수는 기존 `asia-northeast1` 영역 사용. 기존 관계 카운터를 덮어쓰는 마이그레이션 없이 서버에서 집계한다.

| Callable | 입력 | 인증·결과 |
| --- | --- | --- |
| `getMyMeetups` | 없음 | 익명 포함 인증 사용자. 자신이 생성/참여한 모임, `limited` |
| `getMySocialOverview` | 없음 | 등록 사용자. `friends`, `memories`, `limited` |
| `getMeetupMemories` | `meetupId` | 모임 참가자만. 최신 글 최대 100개 |
| `saveMeetupMemory` | `meetupId`, `body` | 등록된 참가자, 불참이 아니며 모임 완료 상태. 서버가 작성자 결정 |
| `deleteMeetupMemory` | `meetupId` | 참가자 본인 글만 삭제 |

저장: `meetups/{meetupId}/memories/{uid}`. 사용자별 모임당 한 글. 수정 저장은 덮어쓰며 날짜는 서버 시각. 모임 삭제 시 기존 재귀 삭제에 글도 포함된다.

모임 참가자(비회원 포함)는 글을 읽을 수 있고 UI에 범위를 설명한다. 외부인은 읽을 수 없다. Firestore 직접 글쓰기는 차단하고 함수에서 검증한다. 작성자가 직접 입력하지 않은 글을 자동 게시하지 않는다.

기존 `privateOrigins` 비공개 규칙을 덮어쓰던 포괄적 읽기 허용을 수정했다. 같은 모임의 다른 참가자도 정확한 출발지 문서를 읽지 못한다. 새 소셜 API는 출발지 좌표·이메일·디바이스 토큰을 반환하지 않는다.

### 성능·범위

- 기존 대시보드 UID별 30초 캐시 유지. 소셜 로딩 실패가 일정 관리를 막지 않게 독립 처리.
- 웹 전체 캘린더는 약속 탭에서 지연 로딩. Journey는 별도 화면.
- 계정 변경 시 개인 화면 상태 초기화.
- 초기 집계는 참여 문서 150개 + 소유 모임 150개 범위, 중복 제거. 초과 시 `limited=true` 표시. 평생 누적 기록으로 오해하게 하지 않는다. 전체 기간 페이지네이션·집계 캐시는 추후 작업.

## 검증과 실행

- Functions: lint/build, 단위 테스트 33개. 미확정/취소/불참 집계, 중복 제거, 작성 권한, 위조 작성자, 길이 제한, 본인 삭제 포함.
- Web: lint/typecheck/프로덕션 build, 테스트 22개. 회원/게스트 분기, 미확정 노출, 탭 전환, 생성 기본값, 저장 실패 시 글 보존, 일본어 메뉴, 헤더 계정 표시, 플랜 검색 버튼·입력 레이블, 시간 저장, 투표 즉시 표시/실패 복구, 요청 분리/중복 방지 포함.
- Flutter: analyze, 테스트 11개. 데이터 변환, 폭 320px·글자 1.5배 친구 카드 포함.
- Firestore 로컬 에뮬레이터: 본인 출발지 허용, 다른 참가자 출발지 차단, 참가자 추억 읽기 허용, 외부인 차단, 직접 글쓰기 차단 6개 통과.
- 새 callable 핸들러도 데모 Firestore에 연결해 비회원 모임 조회, 친구 집계, 추억 CRUD와 외부인/비회원 작성 차단을 실제 읽기·트랜잭션으로 검증. `functions/tests/social-service-smoke.mjs`로 재실행 가능.
- UI: 실제 컴포넌트와 가상 데이터로 데스크톱 / 390px 웹의 게스트 시작·생성·회원 홈·추억 펼치기 확인. 실제 계정으로 운영 서버에 쓰거나 배포하지 않았다.

DOM 테스트의 jsdom은 시스템 Node 22.9와 호환되지 않는다. Node 22.13 이상 최신 22 LTS 또는 Node 24에서 실행한다. 이번 웹 테스트는 제공된 Node 24.19를 사용했다. 웹 build는 시스템 Node에서도 통과했으며 누락된 네이티브 SWC 대신 공식 WASM fallback을 사용했다.

```sh
npm --prefix functions run check
npm --prefix functions test
npm --prefix web run check
npm --prefix web test
npm --prefix web run build
cd mobile
flutter analyze
flutter test
```

```sh
npm --prefix web run preview:social
```

주소: `http://127.0.0.1:4317/tests/preview/index.html`

Plan은 실제 당일 플랜 컴포넌트를 사용하며 검색 결과·일정 추가 등은 로컬 가상 데이터로 동작한다. Controls는 실제 투표 편집기·추천/캘린더·장소/정산·플랜을 렌더링한다. 투표와 추천에만 의도적으로 1.5초의 지연을 주어 요청 중 상태를 확인할 수 있고, Google Calendar 연결은 차단한다.

### 헤더·플랜 정렬 보완

- 비회원/회원 홈에서 헤더와 본문이 동일한 최대 폭 1180px, 좌우 여백(데스크톱 24px / 모바일 16px)을 사용한다. 로고는 왼쪽, 로그인·계정·언어 선택은 오른쪽 기준선에 맞춘다.
- 미리보기도 운영 홈 컴포넌트를 그대로 렌더링해 비회원의 로그인 링크가 빠진 다른 헤더로 검증하지 않도록 했다.
- 당일 플랜의 검색 입력칸과 버튼은 같은 높이 48px, 검색 버튼은 최소 폭 72px·줄바꿈 금지. 종류·시간은 넓은 화면 2열, 작은 화면 1열.
- 취소·완료 버튼은 같은 높이로 정렬하고 작은 화면에서 나란히 동일 너비로 배치한다. 장소 레이블은 입력칸 하나에만 연결한다.
- 브라우저에서 1440 / 768 / 390 / 320px, 한국어·일본어의 10개 조합을 검증했다. 홈 로고·오른쪽 메뉴와 본문의 기준선, 플랜 버튼 높이, 폼 및 페이지 가로 넘침 검사 모두 통과했다.

### 모임 정렬·버튼 응답 보완 (2026-09-08)

- 추천 카드와 캘린더, 장소와 정산 카드 사이 간격을 각각 20px로 통일했다. 캘린더 펼치기는 둥근 모서리·오른쪽 화살표·키보드 포커스 표시를 사용한다. 장소/정산 카드 사이를 관통하던 세로선 대신 섹션 제목에 작은 표시를 두어 내용 왼쪽 기준선을 일치시켰다.
- 장소 추천 모드 변경은 로컬 선택만 수행한다. 외부 API는 명시적인 추천 버튼에서만 호출하고, 추천 중에도 직접 장소 검색을 할 수 있다. 검색 결과가 늦게 도착했을 때 이미 바뀐 검색어를 덮지 않으며, 같은 계정/검색어의 동시 요청은 하나로 합친다. 완료 결과나 실패는 캐시하지 않는다.
- 일정 투표는 선택을 즉시 표시하고 해당 날짜만 저장 중으로 잠근다. 실패 시 서버 기준의 이전 선택으로 돌아오며 오류를 가까이 표시한다. 집계/추천에는 성공한 저장만 반영하고, 저장 중인 투표가 있으면 추천 일정 확정을 잠근다.
- 지출 저장/삭제 뒤 매번 기다리던 정산 요청을 제거했다. 정산은 결과 보기 버튼에서 조회하며, 오래된 응답이나 바뀐 지출의 정산 결과를 표시하지 않는다.
- 당일 플랜 검색과 저장 상태를 분리했다. 검색 중 다른 플랜 조작은 유지하고, 완료/취소에도 요청 중 상태·중복 방지·오류 처리를 추가했다. 최초 모임 구독 실패도 무한 로딩 대신 오류로 표시한다.
- 한국어/일본어 각각 320·390·768·1440px에서 카드 간격, 입력/검색 버튼 높이 및 왼쪽 정렬, 가로 넘침을 검증했다. 1.5초 지연 mock에서도 저장 완료 전 투표 선택 및 저장 중 표시가 즉시 나타났다.
- 실제 Cloud Functions/Google API의 운영 응답 시간은 이번 로컬 검증에서 측정하지 않았다. 서버 콜드 스타트나 외부 API 지연이 모두 해결됐다는 의미는 아니다. 이번 보완은 웹 변경이며 Flutter 및 운영 배포는 포함하지 않는다.

### 정산 순서·장소 지도 보완 (2026-09-08)

- 정산을 장소 선택 영역에서 분리하여 당일 플랜·추억·계정 안내·모임 관리 다음, 모임 페이지 마지막 섹션으로 이동했다. 상단 정산 바로가기는 유지하고, 취소된 모임에서는 기존처럼 숨긴다.
- 당일 플랜에서 검색 결과를 선택하면 장소 이름·주소와 지도 미리보기를 보여준다. 검색어를 다시 바꾸면 이전 선택과 지도를 제거하고, 저장 후 입력 폼의 지도를 초기화한다. 저장된 플랜과 확정 집합 장소에서도 같은 지도 컴포넌트를 사용한다.
- 공식 Maps Embed API를 사용하며 브라우저 전용 제한 키 `NEXT_PUBLIC_GOOGLE_MAPS_EMBED_API_KEY`가 필요하다. 키가 없으면 외부 Google 지도 링크를 표시한다. 서버 키 재사용이나 비공식 키 없는 embed URL은 사용하지 않았다. [설정 안내](./API-연동-가이드.md#웹-장소-지도-설정-maps-embed-api).
- lazy iframe과 저장된 장소의 눌러서 펼치기로 지도 초기 요청을 줄였다. 지도 표시 때문에 폼 저장을 기다리거나 별도 서버 요청을 하지 않는다.
- 웹 테스트 33개, lint/typecheck, production build 통과. 실제 Google iframe 렌더링은 Embed 키 미설정으로 미검증이다. 운영 API 설정 변경·배포·Flutter 변경은 수행하지 않았다.
- 브라우저에서 320px 한국어, 390px 일본어, 1440px 일본어 화면의 정산 위치를 확인했다. 320/1440px의 장소 카드와 전체 페이지에 가로 넘침이 없고, 키 없는 안내/외부 링크 표시를 확인했다.

### 배포 시 주의

이번 작업에서는 배포·push·commit을 실행하지 않았다. 운영 적용 시 함수와 rules/indexes를 먼저 배포하고, 이 브랜치의 웹 이미지를 기존 `aimasho-web` Cloud Run 서비스에 반영해야 한다. 현재 Hosting은 그 서비스로 rewrite하므로 `firebase deploy --only hosting`만으로 새 Next 코드가 배포되지는 않는다.

```sh
npm --prefix functions run build
firebase deploy --only functions:getMyMeetups,functions:getMySocialOverview,functions:getMeetupMemories,functions:saveMeetupMemory,functions:deleteMeetupMemory,functions:getFriendHistory,functions:getMyTravelTimeline,firestore
```

기존 작업의 미커밋 변경사항도 보존되어 있다. 병합 전 해당 변경과 이번 소셜 기능을 함께 검토할 것. 배포 후 테스트 계정 두 개와 게스트 브라우저로 생성→참가→완료→한 줄 기록을 확인한다.
